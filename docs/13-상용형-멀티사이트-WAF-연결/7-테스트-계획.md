# 13-7. 테스트 계획

## 1. 테스트 목표

멀티 사이트 등록, Host 기반 라우팅, 사이트별 정책, 예외 처리, 로그 저장, 인증/인가가 안전하게 동작하는지 확인한다.

## 2. 단위 테스트

| 번호 | 테스트 이름 | 입력 | 기대 결과 | 유형 |
|---|---|---|---|---|
| T1 | domain 정규화 | `Shop.Example.COM:443` | `shop.example.com` | normal |
| T2 | origin URL 검증 | `http://127.0.0.1:3001` | 개발 모드에서 허용 | normal |
| T3 | 잘못된 origin scheme | `file:///etc/passwd` | 거부 | security |
| T4 | metadata IP 차단 | `http://169.254.169.254` | 거부 | security |
| T5 | Host 미등록 | `unknown.example.com` | 404 Unknown Site | failure |
| T6 | 정책 detect | SQLi 요청 | origin 통과 + detected 저장 | normal |
| T7 | 정책 block | SQLi 요청 | 403 차단 + blocked 저장 | normal |
| T8 | WAF disabled | SQLi 요청 | 검사 생략 + origin 통과 | edge |
| T9 | 예외 경로 | `/health` | 탐지 생략 또는 ignored 저장 | normal |
| T10 | IP 차단 | 차단 CIDR IP | origin 전달 없이 403 | security |

## 3. API 테스트

| 번호 | API | 케이스 | 기대 결과 |
|---|---|---|---|
| A1 | `POST /__waf/api/sites` | 정상 사이트 등록 | 200 |
| A2 | `POST /__waf/api/sites` | 중복 domain | 409 |
| A3 | `PUT /__waf/api/sites/{site_id}/policy` | admin 변경 | 200 + audit log |
| A4 | `PUT /__waf/api/sites/{site_id}/policy` | 다른 사용자 site 변경 | 403 |
| A5 | `POST /__waf/api/sites/{site_id}/exceptions` | 사유 누락 | 400 |
| A6 | `POST /__waf/api/sites/{site_id}/ip-policies` | 잘못된 CIDR | 400 |

## 4. 통합 테스트

## 4-1. 로컬 멀티 사이트 라우팅

### 환경

```text
shop.local.test  -> 127.0.0.1:8081 -> Juice Shop A :3001
admin.local.test -> 127.0.0.1:8081 -> Juice Shop B :3002
```

### 테스트

| 번호 | 요청 | 기대 결과 |
|---|---|---|
| I1 | Host `shop.local.test`, `/` | Juice Shop A 응답 |
| I2 | Host `admin.local.test`, `/` | Juice Shop B 응답 |
| I3 | Host `unknown.local.test`, `/` | Unknown Site |
| I4 | Host `shop.local.test`, SQLi payload | shop 정책에 따라 탐지/차단 |
| I5 | Host `admin.local.test`, XSS payload | admin 정책에 따라 탐지/차단 |

## 5. 대시보드 테스트

| 번호 | 화면 | 검증 |
|---|---|---|
| D1 | 사이트 관리 | 사이트 목록 표시 |
| D2 | 사이트 추가 | 저장 후 목록 갱신 |
| D3 | 정책 탭 | detect/block 토글 반영 |
| D4 | 룰 탭 | 룰 ON/OFF 저장 |
| D5 | 예외 탭 | 예외 추가/삭제 |
| D6 | 연결 가이드 | DNS/Caddy 안내 표시 |
| D7 | 탐지 상세 | site/domain/policy_mode 표시 |

## 6. 보안 Abuse 테스트

| 번호 | 테스트 이름 | 입력 | 기대 결과 |
|---|---|---|---|
| S1 | SSRF metadata | `http://169.254.169.254/latest/meta-data` | origin 등록 거부 |
| S2 | 다른 사이트 정책 변경 | 일반 사용자로 다른 site_id 요청 | 403 |
| S3 | Host 헤더 위조 | 미등록 Host | origin 전달 금지 |
| S4 | 로그 XSS | `<script>alert(1)</script>` evidence | escape되어 표시 |
| S5 | 예외 남용 | `/*` 전체 예외 | admin 확인 또는 거부 |
| S6 | sensor token 오류 | 잘못된 token ingest | 403 |

## 7. 회귀 테스트

기존 테스트는 유지되어야 한다.

```text
system/bin/python -m pytest -q
```

특히 다음 기존 기능은 깨지면 안 된다.

| 번호 | 기존 기능 |
|---|---|
| R1 | WAF 차단 페이지 |
| R2 | AI Second Pass |
| R3 | 대시보드 요약/탐지/트래픽 |
| R4 | 사이트 연결 ZIP/설치 스크립트 |
| R5 | 센서 ingest |

## 8. 수동 시연 테스트

| 번호 | 시연 | 확인 |
|---|---|---|
| M1 | 대시보드에서 `shop.local.test` 등록 | 사이트 목록에 표시 |
| M2 | `/etc/hosts` 등록 | 브라우저 접속 가능 |
| M3 | SQLi payload 입력 | 차단 페이지 표시 |
| M4 | 정책을 detect로 변경 | 공격 요청이 통과하지만 로그에는 탐지 |
| M5 | 예외 경로 추가 | 해당 경로에서 차단 안 됨 |
| M6 | Caddyfile 안내 확인 | 실제 서비스 연결 흐름 설명 가능 |
