# 13-3. 데이터 설계

## 1. 설계 목표

현재 `traffic_events`와 `site_profiles` 중심 구조를 실제 서비스형 WAF에 맞게 확장한다.

1차 구현은 SQLite를 유지한다. 단, 테이블 경계를 명확히 해서 나중에 PostgreSQL로 옮길 수 있게 한다.

## 2. 현재 테이블

| 번호 | 테이블 | 역할 | 한계 |
|---|---|---|---|
| 2-1 | `traffic_events` | 요청/차단 로그 저장 | 요청과 탐지 결과가 한 테이블에 섞임 |
| 2-2 | `site_profiles` | site_id, 표시 이름, public_url, WAF on/off | origin, domain, mode, 룰 정책이 부족 |
| 2-3 | `users` | 로그인 계정, site_id, sensor_token | 조직/사이트별 권한 표현이 단순함 |

## 3. 신규/확장 테이블 요약

| 번호 | 테이블 | 목적 |
|---|---|---|
| 3-1 | `sites` | 보호 대상 사이트의 기본 정보 |
| 3-2 | `site_routes` | 도메인과 origin 매핑 |
| 3-3 | `site_policies` | 사이트별 WAF 운영 정책 |
| 3-4 | `site_rule_settings` | 룰별 ON/OFF와 민감도 |
| 3-5 | `site_exceptions` | 예외 경로, 예외 룰, 이유 |
| 3-6 | `ip_policies` | IP 허용/차단 정책 |
| 3-7 | `requests` | 모든 요청의 기본 로그 |
| 3-8 | `detections` | 요청에 매칭된 탐지 결과 |
| 3-9 | `ai_decisions` | AI Second Pass 판단 결과 |
| 3-10 | `audit_logs` | 관리자 설정 변경 기록 |

## 4. `sites` 테이블

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `site_id` | TEXT PRIMARY KEY | 사이트 식별자 |
| `display_name` | TEXT | 대시보드 표시 이름 |
| `owner_username` | TEXT | 소유자 계정 |
| `status` | TEXT | `active`, `disabled`, `pending_dns` |
| `created_at` | TEXT | 생성 시각 |
| `updated_at` | TEXT | 수정 시각 |

## 5. `site_routes` 테이블

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `route_id` | INTEGER PRIMARY KEY | 라우트 ID |
| `site_id` | TEXT | `sites.site_id` 참조 |
| `domain` | TEXT UNIQUE | 보호 도메인, 예: `shop.example.com` |
| `origin_url` | TEXT | 원본 서버 URL |
| `tls_mode` | TEXT | `external_caddy`, `external_nginx`, `none_local` |
| `verify_tls` | INTEGER | origin HTTPS 인증서 검증 여부 |
| `created_at` | TEXT | 생성 시각 |
| `updated_at` | TEXT | 수정 시각 |

## 6. `site_policies` 테이블

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `site_id` | TEXT PRIMARY KEY | 사이트 식별자 |
| `mode` | TEXT | `detect`, `block`, `disabled` |
| `min_severity` | TEXT | `low`, `medium`, `high`, `critical` |
| `ai_second_pass_enabled` | INTEGER | AI 2차 판단 사용 여부 |
| `ai_block_min_confidence` | REAL | AI 차단 최소 신뢰도 |
| `fail_mode` | TEXT | `fail_closed`, `fail_open` |
| `updated_at` | TEXT | 수정 시각 |

## 7. `site_rule_settings` 테이블

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `id` | INTEGER PRIMARY KEY | 설정 ID |
| `site_id` | TEXT | 사이트 식별자 |
| `rule_id` | TEXT | 룰 ID |
| `enabled` | INTEGER | 1이면 활성 |
| `severity_override` | TEXT | 사이트별 심각도 override |
| `updated_at` | TEXT | 수정 시각 |

## 8. `site_exceptions` 테이블

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `id` | INTEGER PRIMARY KEY | 예외 ID |
| `site_id` | TEXT | 사이트 식별자 |
| `path_pattern` | TEXT | 예외 경로 패턴, 예: `/health`, `/static/*` |
| `rule_id` | TEXT | 특정 룰 예외. 빈 값이면 전체 룰 예외 |
| `method` | TEXT | 특정 HTTP 메서드. 빈 값이면 전체 |
| `reason` | TEXT | 예외 사유 |
| `enabled` | INTEGER | 활성 여부 |
| `created_by` | TEXT | 생성자 |
| `created_at` | TEXT | 생성 시각 |

## 9. `ip_policies` 테이블

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `id` | INTEGER PRIMARY KEY | 정책 ID |
| `site_id` | TEXT | 사이트 식별자 |
| `ip_cidr` | TEXT | IP 또는 CIDR, 예: `192.168.0.0/24` |
| `action` | TEXT | `allow`, `block` |
| `reason` | TEXT | 정책 사유 |
| `enabled` | INTEGER | 활성 여부 |

## 10. `requests` 테이블

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `request_id` | INTEGER PRIMARY KEY | 요청 ID |

| `time_iso` | TEXT | 요청 시각 |
| `client_ip` | TEXT | 클라이언트 IP |

| `path` | TEXT | 요청 경로 |
| `query_string` | TEXT | 쿼리 문자열 |
| `user_agent` | TEXT | User-Agent |

| `detected` | INTEGER | 탐지 여부 |
| `blocked` | INTEGER | 차단 여부 |
| `policy_mode` | TEXT | 당시 정책 모드 |

| 컬럼 | 타입 | 설명 |

| `evidence` | TEXT | 탐지 근거 |

## 12. `ai_decisions` 테이블

| 컬럼 | 타입 | 설명 |

## 13. `audit_logs` 테이블

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `id` | INTEGER PRIMARY KEY | 감사 로그 ID |
| `time_iso` | TEXT | 변경 시각 |
| `username` | TEXT | 변경한 사용자 |
| `site_id` | TEXT | 대상 사이트 |
| `action` | TEXT | 수행 작업 |
| `target` | TEXT | 변경 대상 |
| `before_json` | TEXT | 변경 전 값 |
| `after_json` | TEXT | 변경 후 값 |
| `client_ip` | TEXT | 관리자 IP |

## 14. 마이그레이션 전략

| 단계 | 작업 | 설명 |
|---|---|---|
| 14-1 | 기존 테이블 유지 | 현재 화면과 테스트 보존 |
| 14-2 | 신규 테이블 추가 | 기존 데이터 삭제 없이 추가 |
| 14-3 | `site_profiles`를 `sites/site_routes`로 보강 | 기존 public_url을 origin 힌트로 변환 |
| 14-4 | 기록은 이중 저장 | 초기에는 `traffic_events`와 신규 `requests/detections`에 함께 저장 |
| 14-5 | 대시보드 읽기 전환 | 신규 API 안정화 후 화면을 신규 구조로 변경 |

## 15. 인덱스 설계

| 번호 | 인덱스 | 이유 |
|---|---|---|
| 15-1 | `idx_site_routes_domain` | Host 기반 라우팅 빠른 조회 |
| 15-2 | `idx_requests_site_time` | 사이트별 최신 요청 조회 |
| 15-3 | `idx_requests_blocked` | 차단 이벤트 조회 |
| 15-4 | `idx_detections_rule` | 룰별 통계 |
| 15-5 | `idx_audit_site_time` | 사이트별 정책 변경 추적 |
