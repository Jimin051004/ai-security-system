## 3. 1차 구현 범위 권장

1차 구현에서는 아래까지만 완료하는 것이 안전하다.

| 번호 | 포함 | 이유 |
|---|---|---|
| 3-1 | 사이트 등록/수정 API | 전체 기능의 기반 |
| 3-2 | Host 기반 origin 라우팅 | 실제 서비스 연결의 핵심 |
| 3-3 | detect/block/disabled 모드 | 상용 WAF처럼 보이는 핵심 정책 |
| 3-4 | 사이트별 로그 필터링 | 대시보드 연결성 강화 |
| 3-5 | Caddy/DNS 연결 가이드 | 무료 실제 연결 흐름 설명 |

1차 구현에서 보류할 수 있는 항목:

| 번호 | 보류 항목 | 이유 |
|---|---|---|
| 3-6 | 앱 내부 인증서 자동 발급 | Caddy가 더 적합 |
| 3-7 | 외부 알림 연동 | 유료/계정 설정 이슈 가능 |
| 3-8 | PostgreSQL 전환 | 졸업작품 범위에서는 SQLite로 충분 |
| 3-9 | 고가용성 클러스터 | 무료 범위와 구현량 초과 |

## 5. 완료 기준

- [ ] 대시보드에서 사이트를 추가할 수 있음
- [ ] 등록된 도메인 Host로 들어온 요청이 맞는 origin으로 전달됨
- [ ] 미등록 Host는 origin으로 전달되지 않음
- [ ] 사이트별 detect/block/disabled 정책이 적용됨
- [ ] 탐지/차단 로그에 site_id, domain, policy_mode가 남음
- [ ] 일반 사용자는 자기 사이트만 볼 수 있음
- [ ] origin URL SSRF 방어가 있음
- [ ] 기존 `system/bin/python -m pytest -q`가 통과함
- [ ] 무료 DNS/TLS 연결 가이드가 대시보드에 표시됨
