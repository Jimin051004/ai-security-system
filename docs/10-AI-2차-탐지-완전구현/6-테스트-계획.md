# 10-6. 테스트 계획

## 1. 테스트 목적

AI 2차 탐지가 정상 요청을 불필요하게 방해하지 않고, 의심 요청에 대해서만 안전하게 모델을 호출하며, 모델 실패 시 기존 WAF 정책을 유지하는지 검증한다.

## 2. 테스트 케이스

| 번호 | 테스트 이름 | 입력 | 기대 결과 | 유형 |
|---|---|---|---|---|
| T1 | AI 비활성화 | `AI_SECOND_PASS_ENABLED=false` | AI 호출 없음 | normal |
| T2 | 정상 요청 skip | `/` 요청 | suspicious 모드에서 AI 호출 없음 | normal |
| T3 | 의심 요청 호출 | `next=https://evil.example` | AI 호출 조건 만족 | normal |
| T4 | AI 차단 | malicious=true, confidence=0.88 | 403 + `AI-SECOND-PASS` | normal |
| T5 | 낮은 confidence | malicious=true, confidence=0.4 | 통과 | edge |
| T6 | AI allow | malicious=false | 통과 | normal |
| T7 | Ollama timeout | timeout 예외 | 통과, 상태에 timeout 기록 | failure |
| T8 | HTTP 500 | Ollama 500 | 통과, 상태에 http_error 기록 | failure |
| T9 | invalid JSON | 모델이 일반 문장 반환 | 통과, 상태에 invalid_json 기록 | failure |
| T10 | 민감 헤더 마스킹 | Cookie/Authorization 포함 | prompt에 원문 미포함 | security |
| T11 | password 마스킹 | body에 password/token 포함 | prompt에 원문 미포함 | security |
| T12 | 프롬프트 인젝션 | body에 “ignore previous instruction” 포함 | JSON 스키마 외 동작 없음 | security |
| T13 | health AI 상태 | `/__proxy/health` | `ai_second_pass` 필드 포함 | normal |
| T14 | worker AI status | `/__waf/worker/api/ai-status` | 인증 필요, 상태 반환 | security |
| T15 | 대시보드 표시 | AI 차단 이벤트 | 탐지 상세에 AI 배지/신뢰도 표시 | normal |

## 3. 단위 테스트

| 번호 | 대상 | 검증 |
|---|---|---|
| 3-1 | `should_run_ai_second_pass` | mode/enabled/findings/suspicious pattern |
| 3-2 | `_payload_for_model` | 마스킹, 길이 제한 |
| 3-3 | `_parse_json_object` | JSON, markdown-wrapped JSON, invalid JSON |
| 3-4 | `judge_request_with_ai` | HTTP 성공/실패/timeout |
| 3-5 | `verdict_to_finding` | Finding 구조 호환 |

## 4. 통합 테스트

| 번호 | 대상 | 검증 |
|---|---|---|
| 4-1 | `main._run_waf_gate` | AI 차단 시 403 |
| 4-2 | `/__proxy/health` | AI 상태 포함 |
| 4-3 | 워커 로그 API | AI 차단 이벤트 조회 |
| 4-4 | 중앙 대시보드 API | AI finding 표시 |

## 5. 수동 데모 테스트

```bash
ollama serve
ollama pull qwen2.5:7b-instruct
AI_SECOND_PASS_ENABLED=true AI_SECOND_PASS_MODE=suspicious \
python3 -m uvicorn main:app --host 0.0.0.0 --port 8081 --reload
```

데모 흐름:

```text
1. 정상 요청 접속
2. 대시보드에서 AI 상태 ON 확인
3. 기존 룰로 잡히는 SQLi 요청 시연
4. 기존 룰이 애매한 의심 요청 시 AI 2차 판단 시연
5. Ollama를 끄고 fallback 동작 확인
```

## 6. 완료 기준

| 번호 | 기준 |
|---|---|
| 6-1 | AI 비활성화 상태에서 기존 테스트가 깨지지 않음 |
| 6-2 | Ollama 없이도 전체 테스트가 mock으로 통과 |
| 6-3 | 민감정보 마스킹 테스트 통과 |
| 6-4 | 모델 실패 시 요청 경로가 중단되지 않음 |
| 6-5 | 대시보드에서 AI 상태와 AI 차단 이벤트를 구분 가능 |
