# 10-4. 대시보드 설계

## 1. 화면 목적

AI 2차 탐지가 실제로 켜져 있는지, 어떤 모델을 쓰는지, 최근 판단이 성공했는지, AI가 차단한 요청이 무엇인지 운영자가 빠르게 확인할 수 있게 한다.

## 2. 표시 위치

| 번호 | 화면 | 표시 내용 |
|---|---|---|
| 2-1 | 대시보드 Overview | AI 2차 탐지 상태 카드 |
| 2-2 | 탐지·차단 상세 | `AI-SECOND-PASS` 규칙의 공격 유형/신뢰도/사유 |
| 2-3 | 프록시 로그 | AI 차단 이벤트 구분 배지 |
| 2-4 | 설정 또는 사이트 연결 | Ollama 실행/환경 변수 안내 |
| 2-5 | 워커 로그 콘솔 | 해당 워커의 AI 상태 |

## 3. AI 상태 카드

| 항목 | 예시 | 설명 |
|---|---|---|
| 활성화 | ON/OFF | `AI_SECOND_PASS_ENABLED` |
| Provider | Ollama | 현재 제공자 |
| Model | qwen2.5:7b-instruct | 사용 모델 |
| Mode | suspicious | 호출 범위 |
| 최근 상태 | 정상/timeout/invalid_json | 최근 호출 결과 |
| 최근 지연시간 | 812ms | 성능 확인 |
| 차단 기준 | confidence ≥ 0.75 | 차단 임계값 |

## 4. 탐지 상세 표시

AI 차단 이벤트는 기존 룰과 구분되도록 아래 필드를 보여준다.

| 번호 | 필드 | 예시 |
|---|---|---|
| 4-1 | Rule ID | `AI-SECOND-PASS` |
| 4-2 | Attack Type | `Suspicious Redirect` |
| 4-3 | Confidence | `0.88` |
| 4-4 | Reason | `external redirect parameter` |
| 4-5 | Location | `ai.second_pass` |

## 5. 운영자 흐름

```text
1. 운영자가 대시보드 접속
2. AI 상태 카드에서 기능 ON/OFF 확인
3. Ollama 연결 실패면 설정 안내 확인
4. 공격 요청 발생
5. 기존 룰 차단 또는 AI 차단 표시
6. 탐지 상세에서 AI 판단 이유 확인
7. 필요하면 confidence 기준 또는 mode 조정
```

## 6. UI 문구 원칙

| 번호 | 원칙 | 설명 |
|---|---|---|
| 6-1 | AI를 최종 진실처럼 표현하지 않음 | “AI 판단”이 아니라 “AI 보조 판단”으로 표현 |
| 6-2 | 차단 근거를 구조화 | confidence, attack type, reason을 분리 표시 |
| 6-3 | 실패도 정상 상태로 표시 | 모델 미실행은 시스템 장애가 아니라 AI 보조 기능 비가용으로 표시 |
| 6-4 | 민감정보 표시 금지 | prompt 원문, Cookie, Authorization은 UI에 표시하지 않음 |
